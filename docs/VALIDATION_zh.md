# 验证范围

## 公开自动检查

单元测试使用明确的内存测试模型后端及本地临时文件，覆盖 Task/namespace 隔离、
不可变图片、显式历史、版本冲突、去重、取消、deadline、JSON 修复、重启/TTL、
模型/effort 配置及 HTTP 透传。这些测试不代表特定模型服务的能力验证。

发布检查还会在不创建 renderer 的情况下编译和推进程序化 MuJoCo 场景，验证
Forge Python 版本限制，检查发布内容，并构建源码、wheel 和示例 Skill 归档。
CI 不需要模型密钥、私有服务、机器人、相机或预构建 Gateway 二进制。

## 历史操作侧联调证据

一次操作侧基准使用外部配置的多模态服务、MuJoCo RGB-D 以及依靠接触物理的
三轴平行夹爪，包含一次完整物理抓放及三个种子的定位。12 项用例均通过，
包括对未执行动作和未完成任务的正确拒绝。模型及 effort 来自部署配置；
本仓库不分发特定服务的路由名称、原始请求或图片。

该次运行显式使用 8192 token 输出预算和 180000 毫秒 deadline，模型调用墙钟
耗时合计 106.923 秒。三个定位 IoU 为 0.8272、0.8832、0.7746，抓点和放置点
均命中目标 mask。独立物理评估确认目标已释放在托盘中，邻物位移为零。
没有使用 weld 附着，也没有用 oracle 坐标补救。

另一次实际 PAOS/Gateway 验证用七次调用完成流程，耗时合计 7.804 秒：
识别 3.941 秒、几何准备 0.102 秒、加速物理执行 0.203 秒、复核 3.236 秒，
另含能力和观测查询。实际模型/effort 被明确核对，上下文版本从 1 推进到 2。
这些是历史联调证据，未由公开 CI 重现。

更早一次操作侧运行自行选用了其他服务路由，没有遵循已提供的配置。
这些结果没有转记为指定模型的验证；读取器及示例启动脚本已在 0.1.1 修正。
失败尝试保留在本地操作记录中。

## 限制与复现

单次样本不是延迟保证或抓取成功率估计。当前示例是桌面三轴夹爪基准，
尚未验证任意物体、通用机械臂碰撞规划、真机或持续高并发。视觉结论与
独立物理真值分别记录；Schema 有效本身不等于任务成功。

请按[用户手册](../README_zh.md)和[开发手册](../DEVELOPING_zh.md)，使用自己的
模型服务复现。原始输出放在被忽略的 reports 中，记录实际模型/effort，
保留失败与负例；定位失败时不得改用特权仿真坐标继续执行。
